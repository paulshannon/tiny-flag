# Tiny Flag Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable two-team, turn-based capture-the-flag game for the browser, on a farm map with fog of war, built on the game-starter framework.

**Architecture:** Pure rule classes in `games/tiny_flag/sim/` (map, state, paths, vision, resolver, wire filtering, bot) hold the whole game and are unit-tested. A server-only `FlagMatch` runs turns and sends each peer only what its team saw. `TinyFlagGame` (a `GameBase` subclass) carries the RPCs and builds the client: board, order input, HUD and menu. Pieces are drawn from turn messages, never synced nodes.

**Tech Stack:** Godot 4.7.1, statically typed GDScript, `WebSocketMultiplayerPeer`, the repo's `TestCase` runner and `tools/` scripts, Kenney Tiny Farm and Tiny Battle sprites.

**Spec:** `docs/superpowers/specs/2026-10-27-tiny-flag-design.md` — read it before any task; this plan does not repeat its rules.

## Global Constraints

## Review Focus

1. **A person disconnects mid-planning or mid-playback.** The match must not stall: the side passes to a bot at once, and a missing `playback_done` ends at `PLAYBACK_CAP`. Test in Task 8.
2. **Hostile or stale order payloads** (wrong turn, a Dictionary instead of an Array, nested junk, odd-length paths, coords out of range, the same piece twice, an enemy's piece) are dropped without logging an engine error and without dropping the sender's other valid orders. Test in Task 2.
3. **A second person joins mid-turn.** They take the bot's side at the next turn start. The orders already locked for that turn stand, and the newcomer's first `turn_started` view is their side's view, not a stale one. Test in Task 8.
4. **A respawn tile is occupied by an enemy.** The visitor is tagged at tick 1 even though nobody moved; meetings are checked for every pair every tick. Test in Task 4.
5. **A spectator joins mid-match.** Their first message is the previous turn's full outcome, never the current planning positions. Test in Task 8.

### Task 4: FlagResolver

**Files:**
- Create: `games/tiny_flag/sim/flag_resolver.gd`
- Test: `tests/unit/test_tiny_flag_resolver.gd`

**Interfaces:**
- Consumes: `FlagMap`, `FlagState`, `FlagPath` (orders are the `validate_orders` output, piece id → `Array[Vector2i]`).
- Produces: `class_name FlagResolver extends RefCounted`
  - inner `class Outcome: var state: FlagState; var ticks: Array[FlagState]; var events: Array[Dictionary]`
    - `ticks` holds `TICKS` snapshots, one after each tick; after a capture, the remaining ticks repeat the reset board
    - event shapes: `{"tick": int, "kind": "tag", "piece": int, "by": int}`, `{"tick": int, "kind": "pickup", "piece": int, "flag": int}`, `{"tick": int, "kind": "capture", "piece": int, "team": int}`
  - `static func resolve(map: FlagMap, state: FlagState, orders: Dictionary) -> Outcome`: does not mutate `state`; `outcome.state.turn == state.turn + 1`

Algorithm, in order:
1. Respawn pieces tagged last turn onto their home tiles and set `tagged = false`.
2. Compute each ordered piece's entry tick per tile from its running cost. A piece entering a tile at tick `k` is on it from tick `k` on.
3. For `tick` in 1..8: move, then meet, then pick up, then capture, exactly as spec §2 "Resolution". A tagged piece's remaining path is discarded. Meetings consider every Red–Blue pair: same tile now, or each now on the other's tile from before this tick.

### Task 8: FlagMatch (server turn loop)

**Files:**
- Create: `games/tiny_flag/flag_match.gd`
- Test: `tests/unit/test_tiny_flag_match.gd`

**Interfaces:**
- Consumes: Tasks 1–6.
- Produces: `class_name FlagMatch extends RefCounted`
  - `enum Phase { WAITING, PLANNING, PLAYBACK, OVER }`, plus `PLAN_SECONDS`, `PLAYBACK_CAP`, `RESULT_SECONDS`
  - `func _init(map: FlagMap, send: Callable, seed_value: int = 0)`: `send.call(peer: int, kind: String, payload: Dictionary)` with `kind` one of `"turn_started"` (payload `{"seconds_left": float, "view": Dictionary}`), `"turn_resolved"` (a `FlagWire.turn_for` dict) or `"match_over"` (`{"result": int, "score": [int, int]}`)
  - `func add_person(peer: int) -> void`, `func remove_person(peer: int) -> void`
  - `func submit(peer: int, turn: int, raw: Variant) -> void`, `func lock_in(peer: int, turn: int) -> void`, `func playback_done(peer: int, turn: int) -> void`
  - `func tick(delta: float) -> void`: the server calls this every physics frame
  - `func side_peer(team: int) -> int` (0 = bot), `var phase: Phase`, `var state: FlagState`
  - Smoke counters: `var turns_resolved: int`, `var moved: Array[bool] = [false, false]`, `var invalid_orders: int` (orders dropped by `validate_orders`)

Behaviour (spec §1 "Who plays", §2):
- A later `submit` replaces that side's earlier orders, so players can change orders until the turn resolves. A submit after `lock_in` keeps the side locked. A turn resolves when both sides are locked or the timer runs out.
- The first person starts the match with a bot on the other side.
- Bots get `FlagBot` orders at turn start and are locked at once; their `playback_done` is implicit.
- A newcomer takes a bot side at the next turn start; with both sides held by people, they spectate.
- `remove_person` hands the side to a bot at once; if it's that side's turn to lock in or finish playback, the bot does so immediately.
- Spectators get the previous turn's full `turn_for(..., SPECTATOR)` when a turn resolves, and a full view of the state before the current turn.
- `OVER` lasts `RESULT_SECONDS`, then a new match starts on the same sides.

  - `test_first_person_plays_red_against_bot`: `turn_started` sent to the peer with `view.team == RED`.
  - `test_both_locked_resolves_and_sends_each_side_its_own`.
